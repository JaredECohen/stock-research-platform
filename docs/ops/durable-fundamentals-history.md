# Durable fundamentals history

`fundamental_history_service.backfill_fundamentals(ticker, start_date, force_refresh=False)` fills the existing `financial_periods` table without fetching filings/transcripts, creating companies, or invoking LLMs. It requests both annual and quarterly FMP statements, with a request size derived from the requested date rather than the normal eight-annual-period limit. The normal FMP statement API remains unchanged. A provider that returns partial coverage does not suppress later providers; all attempts and remaining gaps are reported. Share-class aliases use the existing symbol-variant policy.

Rows retain the actual provider, reported currency, fiscal period/end, fetch timestamp and availability rule. The natural key remains ticker/period/statement/line item. Missing and nonfinite values cannot replace usable values. Different-provider or currency conflicts retain the stored value and identify the statement, period and line. A same-provider restatement may update a value, keeping its existing availability date; this table is **latest-restated data, not an as-originally-reported revision ledger**. Legacy rows without availability can have it filled on an attributable refresh. Legacy ingests without a real provider identity cannot replace a known provider's value while falsely retaining its provenance.

The public `fundamental_coverage` helper reads the database only. It reports annual and quarterly coverage for income, balance and cash, keyed to revenue, total assets and operating cash flow respectively. Complete coverage requires a dated observation at/before the requested start, no missing fiscal periods through the newest observation, and a newest period no older than 460 days (annual) or 180 days (quarterly). These explicit lag allowances do not guarantee every optional line item exists; rejected/missing primary values are named in the backfill report. Short histories, new listings and provider plan limits remain gaps rather than silently satisfying a two-year requirement. Demo and unprovenanced rows cannot establish coverage.

`read_stored_financials` reconstructs statement rows with source, per-line source and currency metadata, newest first. Use `cadence="annual"` when falling back for existing annual-only valuation/ratio consumers; the default returns both cadences for history inspection. It never seeds a table or reaches a provider. Backfill owns its transaction by default; when supplied a session, it only flushes and reports `committed=false`, leaving commit/rollback to the caller.

No new financial model or migration is required: `FinancialPeriod` already has the necessary columns and unique index. No price ingestion, research prompt, DCF assumption, historical memo, or outcome calculation is changed by this service.
