# Stored memo case compatibility

The September 13, 2026 news run failed for ABBV with `ValidationError` at 06:40:05 UTC. An exact-version, read-only request for ABBV v7 returned HTTP 500 at 06:46:26 UTC. The web traceback identified one invalid field: `bull_case` was a list of dictionaries containing `key_point`, while `StockMemoOut` requires a `BullBearCase` object. Validation failed in `memo_to_pydantic`, before news-impact assessment. The full stored ABBV payload was unavailable from that failed response; its original write provenance has not been established.

`memo_to_pydantic` projects only unambiguous stored `bull_case`/`bear_case` lists: all strings, or all dictionaries with a string `key_point` field. It preserves each point exactly and uses an empty headline because no case-level headline is available. Additional dictionary fields are retained verbatim in the full original case metadata; they are not interpreted as a new headline or research claim. Missing/nonstring points and mixed shapes still fail validation. Each projection adds `Stored memo compatibility` degradation metadata containing the full original case, field name, and source snapshot ID, version and ticker. The stored row is never rewritten. A later valid news patch can inherit this evidence in its new version.

This compatibility adapter is not used for new LLM output. News case patches must remain partial objects with typed `headline`/`key_points` fields. The patched memo is revalidated, and `save_memo` independently validates every publication before opening a database session. This closes a reproduced assignment bypass: a malformed list could previously be assigned to a typed case, serialized successfully and saved, then fail on the next read. That reproduction establishes a possible defect, not the historical cause of ABBV v7.

The focused regressions use real SQLite snapshot reads and the news orchestrator with a stub assessment. They verify exact legacy text and raw-row preservation, visible source identities, rejection of ambiguous legacy forms, additive valid patches, and no publication for malformed new patches. They make no provider or LLM calls. Read-only production readback is required after deployment to verify that the complete stored ABBV shape matches the accepted forms; a failed news run is not retroactively relabeled successful.
