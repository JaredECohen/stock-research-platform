# Historical daily price adapter contract

`get_price_history(ticker, days)` keeps the existing seven bar keys (`date`, `open`, `high`, `low`, `close`, `adjusted_close`, `volume`). `days` requests a span ending today with `ceil(days * 1.6)` calendar days of slack. It is not a result-row cap. Every valid returned date is retained, including provider overfetch, sorted ascending and deduplicated; a conflicting duplicate date rejects the response. Invalid dates and non-finite/nonpositive closes are excluded and counted in logs. Invalid day arguments return unavailable without traffic.

Callers persisting data can copy `provider.price_history_provenance` alongside each successful provider result from `ds._live_chain("prices")`. This class attribute does not inject metadata into ordinary bar payloads or claim all providers use the same adjustment convention. No historical memo outcome is changed by these adapters.

| Provider | Historical request | Existing close mapping | `adjusted_close` meaning |
|---|---|---|---|
| FMP | `/stable/historical-price-eod/full` with explicit `from` and `to`; requests exceeding five calendar years use contiguous windows | Provider full-endpoint `close`, preserved | Same field as `close`; does **not** establish dividend-adjusted total return |
| Tiingo | `/tiingo/daily/{ticker}/prices`, `startDate`, `endDate`, `resampleFreq=daily` | Raw daily `close` | Provider `adjClose`, adjusted for splits and dividends |
| Polygon | Daily aggregates with explicit date range, `adjusted=true`, `sort=asc`, `limit=50000`; follows validated pagination | Existing split-adjusted aggregate `c` | Same split-adjusted `c`, not dividend-adjusted |
| Alpha Vantage | `TIME_SERIES_DAILY`, `outputsize=full` above 100 requested days, otherwise `compact` | Raw daily `4. close` | `None`; this endpoint has no adjusted close |

The official [FMP full endpoint](https://site.financialmodelingprep.com/developer/docs/stable/historical-price-eod-full) supplies OHLCV. Explicit date windows replace the old `limit`-only request; the adapter retains its close mapping and does not call the separate dividend-adjusted endpoint. Five-year request segmentation is our bounded request policy, not a claim that all FMP plans grant five-year access. The publicly retrievable documentation does not establish complete symbol/plan coverage; verify actual stored dates.

[Tiingo's EOD documentation](https://www.tiingo.com/documentation/end-of-day) distinguishes latest-only undated requests from date-bounded history and explains both raw and split/dividend-adjusted fields. [Polygon/Massive's aggregate specification](https://massive.com/docs/rest/stocks/aggregates/custom-bars) documents split adjustment, the 50,000 maximum base-aggregate limit, and `next_url`. Daily timestamps are converted to `America/New_York` dates, independent of server timezone. Pagination URLs must remain on the provider's documented hosts and same ticker endpoint; requests use the configured provider host and key. Cycles, failed pages, unadjusted responses, or exhausted pagination bounds return unavailable instead of a silently incomplete result.

[Alpha Vantage's daily documentation](https://www.alphavantage.co/documentation/#daily) states that `compact` supplies 100 observations and `full` requires a premium key. The adapter uses an already-configured key, never purchases access, and reports `Note`, `Information`, and `Error Message` categories without logging their potentially sensitive bodies. Adding Alpha to a data-service fallback chain is a separate integration choice.

Each normalized result logs provider, ticker, requested span, returned count, actual first/last date, and invalid/duplicate counts. An absent series, invalid rows, or a boundary farther than seven days from the requested date logs `completeness=unverified`. A gap can reflect listing history, holidays, delisting, entitlement, rate limiting, or upstream truncation; it does not prove which one occurred. There is no exchange-calendar completeness claim and no attempt to fill missing dates with synthetic values. A failed FMP window or Polygon page rejects the partial fetch; an empty successful FMP window can legitimately predate a listing and is represented by the actual returned coverage.

Validation is offline with HTTPX request/response fixtures and outbound network blocking. Tests cover multi-year request spans, contiguous FMP windows, pagination failures/host checks/cycles, ET date boundaries, optional adjusted closes, invalid data, complete response retention, unconfigured providers, and secret-free failure categories. No live provider probe, subscription change, or backfill is performed by the tests.
